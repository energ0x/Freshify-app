# Freshify: Огляд проєкту

Короткий технічний посібник для команди щодо архітектури, розгортання та структури проєкту.

## Архітектура

*   **Бекенд:** FastAPI. Використовує SQLAlchemy для взаємодії з базою даних та Pydantic для валідації.
*   **База даних:** PostgreSQL.
*   **Мобільний клієнт:** React Native. Взаємодіє з API та зберігає токени доступу через Expo SecureStore.
*   **ШІ-інтеграція:** Локальна модель Ollama (обробка зображень та тексту). Знаходиться у `gemini_service.py` і повертає типізований JSON.
*   **Авторизація:** JWT-токени (Bearer). Хешування паролів через `bcrypt`.

## Швидкий старт

### 1. База даних

У корені проєкту підніміть PostgreSQL та pgAdmin через Docker:

```bash
docker-compose up -d
```

**Важливо:** `docker-compose.yml` прокидає порт БД на `5435` (а не стандартний `5432`). Оновіть `DATABASE_URL` у файлі `.env` бекенду на цей порт.

### 2. Бекенд

Для запуску сервера потрібен Python, завантажте з офіційного сайту (https://www.python.org).
Перейдіть у директорію `backend/`, встановіть залежності та запустіть сервер:

```bash
cd backend
pipenv install --dev
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

### 3. Мобільний клієнт

Для запуску мобільного клієнту потрібен Node.js, завантажте з офіційного сайту (https://nodejs.org/en/download).
Перейдіть у директорію `mobile/` і виконайте команди:

```bash
cd mobile
npm install
npx expo start -c
```
**Важливо:** перед запуском застосунку оновіть константу `API_URL` у файлі `mobile/src/utils/constants.js`. Замініть дефолтну адресу на ваш локальний IP (наприклад, `192.168.1.100:8000`).

## Структура проєкту (Бекенд)

Логіка розділена на шари, щоб уникнути "товстих" контролерів:

*   `backend/main.py` — точка входу. Тут підключаються роутери та створюються таблиці в БД при старті (`Base.metadata.create_all`).
*   `app/api/routes/` — ендпоінти (`auth.py`, `products.py`, `ai_vision.py`). Лише приймають запити та викликають сервіси.
*   `app/services/` — уся бізнес-логіка (`auth_service.py`, `gemini_service.py`, `product_service.py`).
*   `app/db/models.py` — декларативні моделі SQLAlchemy.
*   `app/schemas/` — Pydantic-моделі для валідації вхідних/вихідних даних API.
*   `app/core/config.py` — налаштування (читаються з `.env`). Для доступу в коді завжди використовуйте кешовану функцію `get_settings()`.

## Важливі нюанси розробки

*   **Робота з БД:** В ендпоінтах використовуйте залежність `get_db()`. Вона автоматично видає сесію SQLAlchemy та коректно її закриває.
*   **Міграції:** Наразі відсутні. Таблиці створюються автоматично при запуску сервера. Якщо схема змінюється, потрібно налаштувати Alembic.
*   **ШІ та зображення:** Клієнт надсилає фото на `/ai/analyze-image`. Бекенд автоматично валідує тип, стискає зображення та передає його в `gemini_service.py`. Відповідь завжди має відповідати Pydantic-схемі `AIProductResponse`.
*   **Токени:** У полі `sub` JWT-токена зашито `id` користувача (UUID). Не змінюйте це поле, оскільки на нього зав'язана логіка отримання поточного юзера (`get_current_user`).
